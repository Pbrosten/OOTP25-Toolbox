- **Blocks:** — <!-- link(s) to tickets that depend on this one, or "—" if none -->

## 1. Problem

What's broken, missing, or painful today, and why it matters. Concrete symptoms
or friction (error messages, repeated manual steps, incidents) over abstract
description. If this was prompted by something observed while doing other work,
say what that was.

## 2. Design choices

The options considered, which one was chosen and why, and what's still
undecided. Prefer this shape per decision point:

- **Question.** Options considered — (a) ..., (b) .... **Chosen: (x)**, because
  ....
- **Outstanding:** anything deliberately left unresolved, and why it's safe to
  defer.

Don't skip this section even for small tickets — a one-line "chosen approach,
no real alternatives considered" is fine when true.

## 3. Approach

The concrete plan: what gets added/changed, in enough detail that someone
unfamiliar with the discussion could implement it. End with the list of files
involved.

**Files involved:**
- `path/to/file` (new|modified)
